# Aura POS 2.0

نظام نقاط بيع وإدارة مطعم/متجر باللغة العربية، مبني على Next.js 16 وReact 19 وTypeScript وTailwind CSS. اسم المنتج الداخلي الظاهر في الواجهة والوثائق هو **Aura POS 2.0**.

## ما الذي يقدمه؟

- شاشة كاشير للطلبات داخل المكان والتيك أواي والتوصيل.
- إدارة قائمة الطعام والتصنيفات والأسعار والعروض والكوبونات.
- فواتير قابلة للطباعة وتصدير تقارير CSV/PDF/JSON.
- لوحة تحكم وتحليلات ومراقبة الإلغاءات والشكاوى والحجوزات.
- مخزون، وحدات قياس، وصفات، أرقام تسلسلية، وتنبيهات نقص المخزون.
- وضع Offline عبر IndexedDB مع طابور مزامنة ومحاولة إعادة الاتصال.
- تكامل اختياري مع WAKZ/WhatsApp عبر API Proxy وWebhook موقّع HMAC-SHA256.

## التشغيل المحلي

يتطلب Node.js 20+ أو Bun. استخدم مدير حزم واحدًا فقط في بيئتك:

```bash
npm install
npm run dev
```

ثم افتح `http://localhost:3000`.

أوامر التحقق:

```bash
npm run lint
npm run build
```

## النشر على Vercel

المشروع متوافق مبدئيًا مع Vercel لأنه تطبيق Next.js قياسي، ولا يحتاج `vercel.json` إضافيًا. اربط مستودع GitHub بالمشروع في Vercel، واترك Build Command الافتراضي أو استخدم `npm run build`، ولا تضبط Output Directory يدويًا.

أضف متغيرات البيئة التالية في Vercel فقط عند تفعيل تكامل WAKZ:

- `WAKZ_BASE_URL`
- `WAKZ_API_KEY`
- `WAKZ_WEBHOOK_SECRET`
- `DATABASE_URL` إذا استُخدم Prisma لاحقًا
- `GEMINI_API_KEY` إذا فُعّلت ميزة Gemini

لا ترفع `.env` أو قاعدة SQLite أو أي مفتاح API إلى GitHub. راجع `.env.example`.

## ملاحظات مهمة قبل الإنتاج

الواجهة الحالية تعمل بدرجة كبيرة كتطبيق محلي: بيانات القائمة والطلبات والخدمات الإدارية الافتراضية محفوظة في الذاكرة/localStorage/IndexedDB، وبعض الخدمات الخلفية ما زالت Stub أو Offline. Prisma موجود كمخطط SQLite لكنه غير مستخدم فعليًا من مسارات التطبيق الحالية. كذلك طابور الـWebhook الموجود في الذاكرة مناسب للتجربة وليس نظام رسائل إنتاجيًا متعدد النسخ.

للاستخدام التجاري الحقيقي، يجب إضافة مصادقة خادمية حقيقية، قاعدة بيانات مُدارة، صلاحيات على مستوى الخادم، تخزين دائم للطلبات والمخزون، وطابور/قاعدة بيانات للـWebhooks.
