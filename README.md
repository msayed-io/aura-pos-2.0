# Aura POS 2.0

نظام نقاط بيع وإدارة مطعم/متجر باللغة العربية، مبني على Next.js 16 وReact 19 وTypeScript وTailwind CSS.

## الوظائف الحالية

- شاشة كاشير للطلبات داخل المكان والاستلام والتوصيل.
- إدارة قائمة الطعام والتصنيفات والأسعار والعروض والكوبونات.
- فواتير قابلة للطباعة وتصدير تقارير CSV/PDF/JSON.
- لوحة تحكم وتحليلات محلية ومراقبة الإلغاءات والشكاوى والحجوزات.
- مخزون، وحدات قياس، وصفات، أرقام تسلسلية، وتنبيهات نقص المخزون.
- وضع Offline عبر IndexedDB مع طابور مزامنة وفحص اتصال محلي.

## التشغيل والتحقق

يتطلب Node.js 20.9+ أو Bun متوافقًا. استخدم مدير حزم واحدًا فقط في بيئتك:

```bash
npm ci
npm run dev
```

ثم افتح `http://localhost:3000`.

```bash
npm test
npx tsc --noEmit
npm run lint
npm run build
```

`npm test` يشغّل اختبارات معزولة باستخدام Node.js، دون إرسال طلبات إلى خدمات خارجية أو طابعة فعلية. لا يحل ذلك محل اختبار الواجهة والطابعة على جهاز التشغيل.

لا ترفع ملفات البيئة أو قاعدة SQLite أو أي مفتاح سري إلى المستودع. `DATABASE_URL` الموجود في `.env.example` يخص مخطط Prisma إذا استُخدم لاحقًا.

## الربط المحلي القادم

تبويب «البوت و AI» متاح في الإعدادات كواجهة فقط، مع شخصية البوت وتعليمات التشغيل وإعدادات الرد وقاعدة المعرفة واتصال واتساب وساعات العمل والردود السريعة وسرعة الإرسال. التنقل وفتح الأقسام يعملان؛ حقول الإعدادات وأزرار الربط والتوليد والرفع والحفظ معطلة صراحة، ولا تقرأ الصفحة بيانات الربط القديمة أو تحفظ بيانات أو تنشئ اتصالات.

لا يوجد حاليًا بوت طلبات أو عميل واتساب مدمج أو مزود ذكاء اصطناعي خارجي. الخدمات الخارجية السابقة ومسارات البروكسي والويب هوك تظل محذوفة. لم تُضف مكتبة بديلة أو خلفية وهمية؛ اختيار المكتبة وآلية الذكاء الاصطناعي ينتظر قرار مالك المشروع.

مسار الطلب العادي محفوظ في `src/aura/POSSystem.tsx`: حفظ الطلب عبر `dashboardOrderService.addOrder` ثم خصم المخزون وتسجيل استخدام الكوبون، ثم طلب طباعة فاتورة المطبخ وفاتورة العميل تلقائيًا. الربط القادم يحتاج تنفيذًا واختبارات فعلية لهذا المسار، وليس مجرد استقبال رسالة أو حدث.

توجد روابط يدوية لفتح واتساب خارج التطبيق، وخطوط وصور وأصوات وأداة قص صور تُحمّل من مواقع خارجية. هذه ليست تكامل بوت أو ذكاء اصطناعي، ولم تُحوّل إلى موارد محلية في هذا التغيير. التطبيق ليس معزولًا تمامًا عن الإنترنت.

## حدود مهمة

الطلبات والقائمة وبعض الخدمات الإدارية تعتمد على الذاكرة أو localStorage أو IndexedDB وبيانات تجريبية. مخطط SQLite عبر Prisma غير مستخدم فعليًا من مسارات POS الحالية، والمصادقة الحالية ليست مصادقة خادمية إنتاجية.

لا يمس هذا التغيير بيانات أجهزة العملاء أو إعدادات حسابات خارج المشروع أو تاريخ Git. إزالة إعدادات محلية قديمة من أجهزة مستخدمة سابقًا تحتاج إجراءً منفصلًا يستهدف بيانات التكامل فقط، دون مسح بيانات البيع.

البناء مضبوط مسبقًا على تجاهل أخطاء TypeScript؛ لذلك يجب مراجعة نتيجة `npx tsc --noEmit` بشكل مستقل، ولا يعد نجاح البناء وحده دليلًا على سلامة الأنواع أو جاهزية الإنتاج.

إجراء GitHub الموجود يشغّل lint واختبارات الانحدار والبناء والتغليف، ثم ينشئ إصدار Windows عند الدفع إلى `master` أو تشغيله يدويًا. النشر يحتاج تفويض المالك؛ استعادة واجهة البوت الحالية مشمولة بتفويضه الصريح لدفع التحديث ونشر إصدار Windows.
